# Running the CourseVault Admin Panel

The admin panel is a React (Vite) app in the `admin-page/` folder. It talks to the Spring Boot backend, so the backend needs to be running too.

---

## 1. Prerequisites

| Tool | Notes |
|---|---|
| **Node.js 18+** | Confirm with `node -v` (npm comes bundled with it) |
| **Git** | To pull the repo |
| **Running backend** | See `backend-setup-guide.md` — the admin panel does nothing useful without it |

---

## 2. Get the code

First time:
```bash
git clone https://github.com/your-username/study-resource-hub.git
cd study-resource-hub/admin-page
```

If you already have the repo:
```bash
cd study-resource-hub
git pull
cd admin-page
```

---

## 3. Install dependencies

```bash
npm install
```

This downloads everything listed in `package.json` into a local `node_modules/` folder. You need to run it:
- the first time after cloning
- again any time someone adds a new package (if the app suddenly errors with "cannot find module", this is usually why)

`node_modules/` is not in the repo on purpose — it's huge and regenerated by this command.

---

## 4. Create your `.env` file (only needed for voice features)

Create a file named `.env` inside `admin-page/` (same level as `package.json`):

```
VITE_VOXIDE_KEY=vox_pub_YOUR_KEY_HERE
```

- Ask the team for the shared Voxide key
- This file is **gitignored** on purpose, so it never gets committed — every person creates their own copy
- If Voxide isn't wired in yet or you don't have a key, skip this step; the admin panel still works fully without voice

---

## 5. Start the backend first

In a separate terminal, run the Spring Boot backend (see `backend-setup-guide.md`) and confirm it's up at `http://localhost:8080`. Quick check: open `http://localhost:8080/api/courses` in a browser — you should see JSON.

---

## 6. Run the admin panel

```bash
npm run dev
```

Vite prints a local address, usually:
```
Local: http://localhost:5173/
```
Open it in your browser. You should see the course list loaded from the backend.

---

## 7. If the backend isn't on your machine

The API address is set in one place: `src/api/client.js`

```javascript
const BASE_URL = "http://localhost:8080";
```

Change it to wherever the backend is running (a teammate's IP like `http://192.168.1.15:8080`, or an ngrok URL). Also update the download links if you changed it — they are built from the same base URL.

---

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Blank course list, browser console shows a CORS error | Backend is missing `CorsConfig.java`, or wasn't restarted after adding it |
| Blank course list, console shows `ERR_CONNECTION_REFUSED` | Backend isn't running, or `BASE_URL` points to the wrong address |
| `npm: command not found` | Node.js isn't installed |
| `Cannot find module ...` on start | Run `npm install` again |
| Downloads/uploads fail but the list loads | Check the backend console for the actual error; make sure the `uploads/` folder exists and matches the shared data (see `sharing-local-data-guide.md`) |
| Port 5173 already in use | Another dev server is running; stop it, or Vite will offer the next free port |

---

## What should never be committed

Already covered by `.gitignore`, but worth knowing if they ever show up as new files in Git:
- `node_modules/`
- `.env`
- `dist/` (production build output)
